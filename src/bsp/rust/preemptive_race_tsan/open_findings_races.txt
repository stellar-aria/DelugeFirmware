# Lens 2 TSan open findings: REAL races on the cluster/loaded/resource-manager/scheduler
# state this harness checks — found by this harness, NOT suppressed, NOT fixed here. These
# fire under sustained playback + concurrent recording once the audio task is genuinely
# preemptive relative to the loader/fiber thread (the Embassy InterruptExecutor target;
# the cooperative BSP is unaffected). run.sh reports matches here as "OPEN FINDING (real,
# not suppressed)" — kept visible in every run's summary, distinct from the broad
# pre-existing baseline in known_patterns.txt.
#
# One extended-regex PATTERN per line (grep -E). By DEFAULT run.sh matches a pattern only
# against the race's normalized one-line SUMMARY (its top/site frame) — same as TSan's own
# summary. Prefix a line with `DEEP ` to instead match it against every frame of both racing
# accesses' full stacks; see known_patterns.txt's header for the full DEEP-tag rationale (in
# short: DEEP is a rare, deliberately-verified opt-in, not a way to write a broader pattern —
# a broad pattern marked DEEP can match an unrelated finding via a shared ancestor frame, e.g.
# every fiber/audio-thread finding shares call-graph-root ancestors). None of the patterns
# below are currently DEEP; all three are already specific function-name SITE matches.
#

# --- [B1] deluge_resource::manager::Manager's Cell<ChunkSlot> chunk table — FIXED (2026-07-19).
#     RETIRED from the active patterns: the four B1 signatures below are commented out so a
#     re-appearance surfaces as UNCATALOGUED (failing the run) instead of being silently
#     absorbed here. Fix = asymmetric fiber-side critical sections around every Manager
#     Cell RMW (crates/deluge_resource/src/sync.rs `Masked` + m_get/m_set/m_rmw, gated on
#     !deluge_in_interrupt()) + a per-thread host critical section (src/bsp/rust/src/services.rs).
#     See docs/dev/known-concurrency-bugs.md (B1). Historical race description kept below.
#     Manager::release (audio thread, via Voice/SampleLowLevelReader unassign ->
#     cluster::remove_reason -> release_lease) races Manager::loader_next / request / acquire /
#     evict_lowest (loader-fiber OR audio thread, picking/leasing the next cluster) on the SAME
#     Cell<ChunkSlot> slot. Manager was written single-threaded (see its own stat() doc) but is
#     reached from Rust-unsafe extern "C" entry points with no lock, so nothing enforces that
#     assumption once C++ calls it from two real OS threads. A non-atomic lease-count RMW race
#     can silently lose an update -> premature eviction of a still-playing cluster, or a queued
#     flag never cleared -> the loader spins on a phantom queue entry. Reached from BOTH
#     playback (Voice::render -> SampleLowLevelReader::moveOnToNextCluster -> SampleStream::
#     get_cluster -> deluge_resource_request -> Manager::request) AND — now that B2/B3 are
#     fixed — the recorder (SampleRecorder::createNextCluster -> get_cluster -> Manager::request).

#Cell<deluge_resource::manager::ChunkSlot>
#core::mem::replace::<deluge_resource::manager::ChunkSlot>
